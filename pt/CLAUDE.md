# PT Pal

The owner's PT motivator: after each physical therapy set, tap a berry to feed their pal. Red **Sweetberry** = daily PT (counts toward the flame and a daily goal), gold **Cragberry** = climb day PT, which also counts toward the daily goal (names the user picked; the code and database still say `daily` and `climb`) (the owner has no set climbing days, so they pick which berry to throw). One user: only the owner's login gets in (`pt_owner`).

## How it's built

## Data

- `pt_settings(id, name, daily_goal, photo_at, lat, lon, rug, hat, year_seen)`: one row. `rug` the rug's id from `RUGS` (lowercase letters only), null = braided (`migrations/2026-11-13-rug.sql`). `hat` jsonb `{x, y, w, r}` (the Santa hat on the photo; null = not placed), `year_seen` the year whose New Year screen was shown (`migrations/2026-11-13-hat-and-new-year.sql`). `daily_goal` 1–10. `photo_at` null = no photo. `lat`/`lon`: the owner's location rounded to 0.1° (about 10 km) for the window's real sunrise and sunset, null = not set (`migrations/2026-11-13-window-location.sql`). The page selects `*`, so it still loads before a new column's SQL is run.
- `pt_feeds(id, kind, fed_at)`: one row per berry, `kind` daily or climb.
- Storage bucket `pt-photo` (private, 2 MB, PNG/JPG/WebP): one file, `pal`. Policies on `storage.objects` let only the owner read, add, change, or delete it, and only under that name.
