# Top Out (Adult Team)

Coaching for the gym's Adult Team, a group instead of one student at a time. Staff sign in; team members don't (yet). Each location (Minneapolis, St. Paul, more added by admins) has a roster, a Team Summary with a Team Focus, and a calendar. Each member has an Intake, Goals, Coach Notes and Check-ins.

## How it's built

- Same shape as Sit Start: `index.html` (header and shell), `styles.css`, plain JS in `js/` loaded as classic `<script>` tags that share one global scope, in the order listed in `index.html`; `boot()` runs last. Don't declare the same top-level name in two files. No build step. supabase-js pinned from jsDelivr.
  - `core.js`: `CONFIG`, page state (`me`), helpers (`esc`, `para`, `flash`, `ask`, `busy`, `crumbs`, field errors), pronouns, dates, grades (`V_GRADES`, `ROUTE_GRADES`, `circuitRange`, `swatch`), `sendLink`.
  - `app.js`: `boot`, `loadMe`, `route`, the leave check and Unsaved marks, sign-in pages, Home (`homePage`), `eventRow` / `KINDS`.
  - `location.js`: a location's tabs, in order Summary (`#/loc/<id>`, where a location opens; the user asked), Calendar, Team; `#/loc/<id>/team` (Team tab: members with chips, Active / Moved / Former (Moved and Former only when someone is in them), + Add Member; the member page's breadcrumb goes back here) and `#/members` (Team Members: everyone you can see with their team chips, a Location: filter incl. On Several Teams; a Home tile for all staff). Both use `loadMembers` / `membersView`. Opening Home resets the list to Active. Members with the same name (in the list shown) get a line under the name: Joined Mon YYYY · email. Add Member first checks for the same first and last name (`notADuplicate`: This Person May Exist on Another Team, each as Name (pronouns), where they are, then Add to <location>; OK is Add New Person; both plain until hovered, `.hover-fill`, the user asked) and lists them: members you can see as links (put the same person on this team via Details instead), the rest from `team_same_name()` (security definer: their id, locations and whether they left). Each has Add to <location>: `team_join_location()` puts them on this team even if the coach doesn't coach their other teams (the user asked: no admin needed), then opens them. Or Add Anyway.
  - `calendar.js`: `#/loc/<id>/calendar` (month grid, the picked day, Coming Up, the event dialogs).
  - `member.js`: `#/member/<id>` (Exit Intake for a Former member, Intake, Goals, Left Before / Earlier Exits, Coach Notes, Details). Intake and Exit Intake labels use the member's pronouns (`pronounWords` gives subj/obj/pos/self/plural, `Cap`): Why She Joined, What They Want (the user asked).
  - `exits.js`: `#/exits` (Why Members Left, a Home tile for all staff: Location: and Left Since filters, a Reasons tally, Would They Come Back?, then each exit; Back on Team when they came back; admins get Delete Exit Intake on each, the user asked, which leaves `left_on` as is).
  - `checkins.js`: the Check-Ins card and its dialog; `AREA_GROUPS`, `byGroup`, `areaChips`, `answered` (shared with summary.js).
  - `summary.js`: `#/loc/<id>` (the Summary tab, first; `/summary` still works). It replaces the coach's spreadsheet: each active member's latest check-in (Check-Ins Since: a date, by default the 1st of the month 6 months back (the user asked), or Show Latest Check-Ins for the latest whenever it was), By Area (Member and Coach averages with how many rated, a count per tag question, Most Wanted and Lowest Rated lines, a highlight when they differ by 1+), Check-In Answers (By Question / By Member; was What They Said, renamed with a hint line since the user found it unclear; a team can be ~30 people, so By Question shows the first `SAID_SHOWN` (5) answers per question with Show All N Answers / Show Fewer (`details.said-more`), and By Member folds each member to a line; the user asked for a limit), and Team Focus. Next Practice (right column, above Check-In Answers; the user asked): the next event of kind Practice here from today, with what the calendar pop-up shows less the type and location chips (the user said the page makes those obvious) and the Added by line, the linked plan's Focus Areas, its Practice Plan and Open in Calendar (sets `calOpen`, so the pop-up opens). Below it, Heads Up: Injuries or Limits lists active members whose intake has injuries (`headsUpHTML`, the user asked). Only active members count (Former ones are left out). Copy Summary (plain text) and Copy Table (tab-separated, one row per member, pastes into a spreadsheet) are for coaches not on the app yet (the user asked). Team Focus shows only here (the strip on the other tabs was dropped once Summary became the first tab; the user asked).
  - `practices.js`: `#/practices` (a Home tile for all staff: search, and under it Focus Area pills with counts, pick several = any of them, Clear; the user asked for pills instead of a dropdown; a Sort: pick between the search and the pills, Name / Recently Used / Longest / Shortest; each card says Last used <date> at <location> · Next: <date> at <location> from `team_events.practice_id` (the user asked for the place; same-day events merge as A + B, none for Every Location), only events the coach can see) and `#/practice/<id>` (the plan: each block with its length, no start or clock times (the user said); About; where it is On the Calendar), Delete is on each list card (the name is a link stretched over the card, so a button fits inside), on the practice page and in the editor (`deletePractice`). Duplicate (by Edit) saves a copy named "<name> (Copy)" at once and opens it in the editor. Practice Plan on the Summary's Next Practice and on a calendar event opens `practiceDialog` instead of the page (the user asked, to stay on the location): the plan, then Edit swaps in the editor's fields (`practiceFieldsHTML`, `wirePracticeForm`, `readPractice`, shared with the editor page); Opened from an event (calendar or Next Practice, which pass the event), the editor has Save to This Event Only (`team_event_practice()`: a one-off copy, `event_only` with `based_on` = the original, linked to just that event; the event's own one-off is changed in place) and Save to Original Practice (changes the library practice everywhere; a red line above the fields says how many events use it; the user asked). No Delete beside the two saves (four buttons didn't fit on a line; Delete is on the practice page), and on a narrow screen the buttons share the lines evenly (`ask` `alt` adds `.many`: Cancel on the left, the two saves on the right; the user asked). A coach who can't change the event gets only Save to Original. Editing a one-off again just saves it (Save One-Off Practice, no choice, no red line; the user asked). A one-off no event links to is deleted (trigger `team_drop_unused_one_off`). One-offs stay off the list unless the Show One-Offs switch is on (`.switch`, a checkbox with role="switch"; the user asked for a toggle) (then only one-offs show; the user asked), off the event's Practice Plan pick (but the one it has, as "(This Event Only)"; on the event and Next Practice buttons that sits on its own line under the name, `.plan-one-off`, a column since buttons are inline-flex), and an original's Last used, Next and On the Calendar count its one-offs' events. Migration `2026-10-02-practice-one-offs.sql`. Save redraws the page and reopens the plan; Open Practice Page goes to the page. `#/practice/<id>/edit` and `#/practice/new` (the editor: blocks reorder by grip, the hidden `order` field makes a reorder, add or remove count as unsaved; empty blocks are dropped on save).
  - `admin.js`: `#/staff` and `#/settings` (admins only). Settings has two columns: Locations and Circuit Colors on the left; Check-In Questions and Focus Areas on the right. Every list there reorders by dragging its grip, which replaced the ↑/↓ buttons (the user asked). `wireGrips` / `GRIP` (core.js) are shared with the practice editor: pointer events so fingers work too, listened for on the window (moving the row drops pointer capture), arrow keys when the grip has focus. Rows: the name (and group) on the first line; `.set-line` puts the example answer, the checkboxes and the buttons on lines under it, so every name box is the same width (the user asked); circuit rows stay one line with Save and Delete together (`.set-btns`). Ticking Rated shows Focus Area Ratings at once. + Add for a location takes the Shorthand too, and so does Home's + Add Location.
- **Same Supabase project as Sit Start** (same URL and key in `CONFIG`). Tables are all `team_*`; `supabase/schema.sql` creates them. Security is in the database: every table checks `team_staff` through `team_is_staff()`, `team_is_admin()`, `team_can_location()` and `team_can_member()` (read rules use `team_my_locations()` and `team_my_members()` instead, the same answer worked out once per query rather than per row; migration `2026-10-03-faster-reads.sql`), so a login that is only a Sit Start account signs in and sees nothing (the page shows "No Access").
- **Shared logins:** `auth.users` is shared. Sit Start's sign-up gate, Delete Student, Delete Staff and Deactivate call `login_in_other_app(email)`, which Top Out's schema defines (is the email on `team_staff`?), so Top Out staff can create a login and Sit Start never deletes or signs out one Top Out uses. Removing someone from Top Out staff keeps their login. Sign Out here is this device only (`scope: 'local'`).
- **Shared emails:** Supabase has one template per email for the project. `supabase-emails/build.sh` (repo root) joins `topout/supabase/emails/*.html` and `sitstart/supabase/emails/*.html` into `supabase-emails/*.html` with `{{ if .Data.topout }}`; those are what get pasted into Supabase. `sendLink` passes `topout: true` for a new login and `team_stamp_sender()` writes it (and `sent_by`) on an existing one; Sit Start's `stamp_sender()` sets it back to false.
- Switching a location's tabs (Summary, Calendar, Team) skips the Loading step: `locationPage` keeps the shown tab (its `nav.tabs[data-loc]`), lighting the new tab at once, until the next one draws (the user asked).
- `redraw()` re-runs the route after a save, without the Loading step and keeping the scroll (`redrawing` in `view`). `navToken` stops a slow page drawing over a newer one. It also keeps unsaved edits in the other `data-save` forms (`keepEdits` in app.js, like Sit Start's): forms are found again by id or `data-kind` + `data-id`, the one just submitted is skipped, and the values go back a frame after the draw with input/change events. A new `data-save` form needs an id (or `data-kind`) to be kept.
- Notes take **bold**: `rich()` (core.js) puts a Bold button on a textarea (Ctrl+B too), on every box whose text `para()` shows (Coach Notes, Team Focus, event notes, check-in answers and notes, practice summary and block notes); not on intake or exit fields. Every textarea grows to fit its text: CSS `field-sizing`, and `grow` / `growAll` where it's missing (iPhone Safari), run by `view()`, `ask()`, typing, focus and unfolding a card.

## Accounts

- `team_staff(id, email, first_name, last_name, name, pronouns, roles, invited_at, owner)`: `roles` ⊆ {admin, coach}. Admins see every location, the Staff page and Settings. Coaches see the locations in `team_staff_locations(staff_id, location_id)`. The owner (set only in the SQL Editor) always keeps Admin and can't be removed (`team_protect_owner`); there is always an admin (`team_keep_an_admin`); nobody removes themselves or takes Admin off themselves.
- Staff page: + Add Staff inserts the row, ticks locations and sends the invite (`sendLink`, then `invited_at`). Typing an email Sit Start knows (`team_staff_lookup`, admins only: Sit Start staff, else students) fills in any empty name and pronoun fields (`watchLookup`, `setPronouns`), and if that login already has a password (`encrypted_password` set) there is no invite: they are added, `invited_at` is stamped, and they sign in with the password they have (the user asked for no password change). Sit Start's Add User does the same the other way, through `person_in_other_app()`, which this schema replaces to read `team_staff`. Clicking a person opens the same dialog to change name, roles and locations, Remove them, or use the Resend Invite / Email a Sign-In Link button (sends at once; the result shows in the dialog, since a flash would sit behind it; the user wanted a button, not a checkbox). Status: Active (has signed in), Invited, Not Invited.
- **One name everywhere:** `person_pull` / `person_push` triggers (this schema) keep first name, last name and pronouns the same on `staff`, `students` (Sit Start) and `team_staff` rows with the same email (the user asked for this). A row that newly gets an email someone already has, or has no first name, adopts the existing name; after that any change copies to the others (last save wins). `team_members` are not logins and are not synced.
- Sign-in pages copy Sit Start's: password sign-in, Forgot Password (same answer either way), Choose a Password after a link (`?setpw=1`).

## Data

- `team_locations(id, name, short_name, position)`: Home's cards in `position` order (a solid orange line on top). `short_name` is the gym's shorthand (MBP, SPBP; the user asked), set in Settings, '' = none; `locShort(l)` (core.js) gives it or the name. Chips and short lines use it (Team Members and Also on / Now at chips, Staff chips, Home's Coming Up, calendar Also / location lines, Why Members Left, the Practices used line); headings, filters, pick boxes, buttons and the duplicate check keep the full name. Migration `2026-10-02-location-short.sql`. A location with members can't be deleted (FK restrict on `team_member_locations`).
- `team_member_locations(member_id, location_id, inactive_on)`: the teams a member is on, usually one, possibly several (the user asked for this). `inactive_on` set = inactive on that team (switched locations but kept on its list; the user asked): Details has an Active / Inactive pick by each ticked team; there they show under Moved with a Moved <date> chip and Now at X for the teams they are active on, and they are left out of Home counts and the Summary; an active member shows Also on X for their other active teams (inactive ones get no chip; the user dropped Formerly X); on Team Members, a picked location puts them under Moved if inactive there, All Locations only if inactive on every team. Former is only for people who left Adult Team (`left_on`). Add to <location> on an inactive one makes them active (`team_join_location`). `inactiveOn(m)` in location.js. Migration `2026-10-02-inactive-teams.sql`. Left the Team (`left_on`) is still for leaving Adult Team. `team_can_member` = admin or a coach at any of their teams. A coach adds or takes off only their own locations; Details shows Teams checkboxes (at least one) and a hint for teams they can't see. New members come in through `team_add_member()` (security definer: member and first team together, since a member with no team can't be read back). The member page's breadcrumb goes back to the list they came from (`lastLoc`: a location they're on, or `'members'`).
- `team_members(id, first_name, last_name, name, pronouns, email, joined_on, left_on, intake_*)`: `left_on` set = Former (Left the Team and Delete Member: admins only, greyed out for coaches with a hint line, no hover text; the user asked. The database enforces it too: trigger `team_only_admin_leaves` on setting `left_on` (clearing it is fine for coaches; the SQL Editor is not blocked) and the "admins: delete" policy; migration `2026-10-02-admin-leave-delete.sql`). Left the Team marks every team inactive (trigger `team_member_left`, so teams the coach can't see too; migration `2026-10-02-left-team-inactive.sql`). Back on Team clears `left_on` and asks for one location to make active (`team_join_location`); the other teams stay inactive (the user asked). Intake is filled in by a coach: why they joined, what they want from Adult Team, comps (yes/maybe/no/''), injuries or limits, anything else. The user said no availability (practice days are fixed). An empty intake (why and wants) shows Needs Intake.
- `team_exits(member_id, left_on, reasons, details, better, come_back, joined_why, joined_wants, author_*)`: Exit Intake (the user asked), one row per time they left (kept if they come back). The Left the Team dialog asks it (all optional) and always inserts a row; a Former member's page edits the row for their current `left_on` (or inserts one for someone who left before this existed). `reasons` are keys of `EXIT_REASONS` (member.js; don't rename a key), `come_back` '' / yes / maybe / no. Why They Joined / What They Wanted (`joinedForHTML`) show beside it in the dialog, the card and on Why Members Left (the user asked); the dialog shows the intake as it is, the card and Why Members Left show the exit row's copy (`joined_why`, `joined_wants`), taken on insert by trigger `team_exit_snapshot` and never changed after, so a later Save Intake doesn't change it (the user asked; migration `2026-10-02-exit-intake-snapshot.sql`). The card shows no Added by name (the user asked); the row is still stamped. RLS `team_can_member`, admins delete. Migration `2026-10-02-exits.sql`.
- `team_goals`: current / achieved / archived; `team_goal_done` sets `done_at`.
- `team_coach_notes`: `note_date` (practice) or empty (general). Author or admin edits/deletes. `team_stamp_author` signs notes, check-ins and events.
- `team_circuits(name, color, position, v_min, v_max)`: the gym's circuit colors, easiest first, same at every location: Yellow V0, Red V0–2, Green V1–3, Purple V2–4, Orange V3–5, Black V4–6, Blue V5–7, Pink V6–8, White V8–10, Mint V11+. - `team_events`: calendar, `kind` competition / practice / open_house / other, one day or several (`end_date`), all day or timed, place, notes. `location_ids` = the locations it shows at (the Show At boxes), null = every location (admins only; ticking Every Location ticks every box). ## Conventions

- Look: "Chalk & Rope": chalk-white page, deep navy ink, rope-orange accent; Space Grotesk headings, Figtree body. Tokens on `:root` with dark mode. The user's fallback if they go off it: "Granite & Sky" (cool grays, slate-blue accent).
- Logo: a boulder with a flag on top (inline SVG in the header and on the root home card; `icon.svg` is the favicon). `apple-touch-icon.png` (180px, chalk mountain and orange flag on navy) is for phone home screens, drawn with PowerShell System.Drawing from the same points as the SVG, so redraw it if the mark changes.
- Works at ~400px wide. Title case for buttons, headings and labels; sentence case for hints and messages.
- Dialogs use `ask()` (`wide` for big forms, `extra` for a Delete/Remove button, `alt` for a second save button, `onOpen` to wire fields, `cancelLabel`). One `#dlg` for all: its close event comes late, so `ask()` skips a close while its own form is up (one pop-up opening another, like Practice Plan from an event). `wireGrips(moved, root)` takes the form to look in. On a touch screen `ask()` focuses the dialog, not its first text box, so the keyboard doesn't pop up (the Staff dialog did).
- Cards fold: every `section.card` whose first child is an h2 (or a `.row` starting with one) gets its title turned into a `.fold-btn` by `foldCards()` (core.js, run by `view()`; the user asked). Folded cards are remembered on the device by title (`localStorage` `topout.fold`, digits ignored). `data-fold` starts a card folded and remembers it per page for the visit only: a filled-in Intake and Exit Intake, and Details on a member page (the user asked). `data-nofold` for cards whose title changes (the calendar's month and picked day).
- An open pop-up locks the page behind it (`html:has(#dlg[open])` overflow hidden; phones scrolled it).
- Focus Area pills (`areaChips`: Team Focus, check-in tags): on a phone (≤560px) each group's name is on its own line with its pills under it (the user asked).
